## 計測構成

LP → dataLayer → GTMウェブコンテナ → GA4標準プロパティ。

Googleタグ1個による自動page_viewと、カスタムイベントトリガー1個によるbooking_site_clickタグ1個を使用します。GTM設定は手順書に記載し、未検証のコンテナインポートJSONは付属しません。

LPにGoogle Analyticsの直接送信処理はなく、GA4タグはGTMだけで設定します。JavaScriptで構成するため、JavaScript無効時はクリック計測せず、GTMのnoscript iframeは追加していません。予約リンクはJavaScript無効時も通常のリンクとして動作します。

## イベント

```json
{
  "event": "booking_site_click",
  "store_id": "kichijoji",
  "store_name": "シミケア専門店 Areum 吉祥寺店",
  "lp_id": "areum-kichijoji",
  "booking_url": "https://i3ay4k.b-merit.jp/T9DsWS/web/reserve2/?no_menu=1&redirect=1",
  "button_location": "store_button"
}
```

店舗メタデータはGTM起動前にdataLayerへ入れ、Googleタグの共有イベント設定でページ閲覧にも付与します。別店舗を追加する際は、そのLPのconfigのstoreId/storeName/lpIdを変更します。今回の実装・計測対象は吉祥寺店のみです。

UTMはGA4の標準機能でLP URLから収集します。LPのURLや予約先URLを書き換えず、独自のUTM保存用CookieやlocalStorageは追加しません。

## 重複防止の範囲

- ページ内のリスナーは1組だけ。同じファイルを再読み込みしても追加しません。
- 同じイベントオブジェクトを複数処理しません。
- 同じリンクへの750ms未満の連打は1回。別のリンク・時間を空けたクリックは別の操作として記録します。
- 左クリック・タッチ・キーボードはclickだけで計測。中クリックはauxclickだけで計測。右クリックは計測しません。
- 既存の標準GTM/GA4スクリプト、既存GTMの実行情報、gtag関数を検知した場合、追加のGTMを自動ロードしません。既存GTMがあればそのコンテナ側にイベント設定を追加します。
- 手順書でGA4の自動外部クリックと別のクリックトリガーを併用しないよう指定。ページビューの別タグも追加しません。

第三者がGTM管理画面で同じイベントタグを複数作成した場合まで、LPのコードだけでは防げません。GTM側の設定とプレビュー確認を含めて重複を防ぐ構成です。

## 完了した検証

自動テスト9件が成功しました。

1. 追加したscript要素とdata属性を除けば元HTMLと完全一致。CSS・画像・リンクURL・別タブ動作に差分なし。
2. ID未設定時はGoogleへのリクエストなし。メタデータとイベントはdataLayerに準備。
3. 有効形式IDでGTMを1回だけロード。メタデータが先に入ることを確認。
4. 既存GTM/直接GA4等の検知時は追加ローダーを抑止。
5. 同じイベント・連打の抑制と、その後の意図的な再クリックの記録。
6. 4か所すべてのリンクと子要素からの識別。
7. 中クリック・右クリック・対象外リンク・無効URL・キャンセル済みイベントの処理。
8. 既存dataLayerとUTM保持。予約URLにパラメータ追加なし。
9. 無効なGTM IDでリクエストを出さない。

実ブラウザでも、検証用iframe内の実LPにある4個のリンクを作動させ、設置場所の異なる4個のイベントと全パラメータ、重複ファイル読み込み時の抑止を確認しました。生の結果は `browser-verification.json` に保存しています。この検証ページだけで外部遷移をキャンセルし、本番のスクリプトはpreventDefaultや遷移待ちを使いません。
