# Areum 吉祥寺店：最初に一度だけ行う計測設定

実装日：2026年11月11日

GitHub保存先：https://github.com/lime2002-esthetic/areum-pages

公開LP URL：https://lime2002-esthetic.github.io/areum-pages/

LPのコードは準備済みです。現時点ではGTM・GA4のIDが未発行のため、Googleへの計測送信は始まっていません。以下の設定とGitHubへの反映後に有効になります。

使うのは標準のGoogleアナリティクス（GA4）と、Googleタグマネージャーの「ウェブ」コンテナです。この実装には有料の計測サービス、サーバー、サーバーコンテナ、Google Cloud、Analytics 360は不要です。

## 1. LPの保存場所と公開URLを確認する

1. [GitHub](https://github.com/)に普段のアカウントでログインします。
2. 右上のプロフィール画像 →「Your repositories」を開きます。
3. AreumのHTMLを入れた保存場所を開きます。ブラウザのアドレスが `https://github.com/アカウント名/保存場所の名前` となるページです。このURLをCodexへ送れば、ファイルの反映作業を引き継げます。
4. 保存場所の「Settings」→「Pages」に表示される `https://…github.io/…/` が公開LPのURLです。GitHubの管理画面URLとは別です。

保存先が分からないときは、GitHub画面のアドレスをそのままCodexへ送ってください。既存Belle用リポジトリをAreum用だと決めつけて上書きしないでください。

## 2. Googleアナリティクスで「G-」のIDを取得する

1. [Googleアナリティクス](https://analytics.google.com/)を開き、会社で継続管理するGoogleアカウントでログインします。
2. 初回は「測定を開始」からアカウントを作成します。アカウント名は会社名、プロパティ名は `Areum LP` などにします。タイムゾーンは日本、通貨は日本円にします。既に会社用GA4があれば、新規作成前に管理者に確認します。
3. データ収集のプラットフォームで「ウェブ」を選びます。
4. ウェブサイトのURLに手順1の公開LP URL、ストリーム名に `Areum 吉祥寺店 LP` を入力します。
5. 作成後、「管理」→「データの収集と修正」→「データストリーム」→該当のウェブストリームを開きます。
6. 「測定ID」の **`G-` から始まる文字列**をコピーします。数字だけのプロパティID・ストリームIDではありません。
7. 同じストリームの「拡張計測機能」の歯車を開き、「離脱クリック（外部リンククリック）」をオフにします。外部クリックは今回の `booking_site_click` だけを使います。
8. 「ページビュー」の詳細設定がある場合、ページ読み込み時の計測は有効のままにし、「ブラウザの履歴イベントに基づくページの変更」はオフにします。このLPのページ内移動を追加PVとして数えないためです。

ここで表示されるGoogleタグのHTMLはLPに貼りません。GA4はGTM経由に統一します。

公式：[測定IDの確認](https://support.google.com/analytics/answer/9539598?hl=ja)

## 3. Googleタグマネージャーで「GTM-」のIDを取得する

1. [Googleタグマネージャー](https://tagmanager.google.com/)を開き、同じ会社用Googleアカウントでログインします。
2. 「アカウントを作成」を選び、アカウント名は会社名、国は日本にします。
3. コンテナ名は `Areum LP`、ターゲットプラットフォームは **「ウェブ」**を選択して作成します。サーバーは選びません。
4. 画面上部の **`GTM-` から始まる文字列**をコピーします。表示される設置用HTMLを別途貼り付ける必要はありません。
5. `assets/js/analytics-config.js` を開き、次の空欄1か所に入力して保存します。

```js
gtmContainerId: "GTM-ここを実際のIDに置き換える",
```

`storeId`・`storeName`・`lpId`は吉祥寺店の情報で設定済みです。変更は不要です。`G-…`のIDをこのファイルに入れないでください。IDをCodexに送れば、この1か所の変更も引き継げます。

公式：[アカウントとコンテナを作成](https://support.google.com/tagmanager/answer/14842164?hl=ja)

## 4. GTMで変数・タグを設定する

Google側の画面名は表示言語・更新で少し変わる場合があります。下記の名称・値をそのまま使ってください。

### 4-A. 5個の「データレイヤー変数」を作る

GTM左側の「変数」→「ユーザー定義変数」→「新規」を開き、「変数の設定」→「データレイヤーの変数」を選びます。バージョンは「2」のままで、次の5個を1個ずつ作成します。

| 保存する変数名 | データレイヤーの変数名 |
| --- | --- |
| DLV - store_id | store_id |
| DLV - store_name | store_name |
| DLV - lp_id | lp_id |
| DLV - booking_url | booking_url |
| DLV - button_location | button_location |

左列はGTMで管理する名前、右列は入力欄の値です。大文字・小文字を変えないでください。

### 4-B. 共通設定の変数を1個作る

「変数」→「新規」→「Googleタグ：イベント設定」を選択します。名前は `EVS - Areum common` にします。「イベントパラメータ」に以下を入力します。値は入力欄右の変数選択ボタンから4-Aの変数を選べます。

| パラメータ名 | 値 |
| --- | --- |
| store_id | {{DLV - store_id}} |
| store_name | {{DLV - store_name}} |
| lp_id | {{DLV - lp_id}} |

### 4-C. ページ閲覧を送るGoogleタグを1個作る

「タグ」→「新規」を開きます。

| 設定項目 | 入力・選択する内容 |
| --- | --- |
| タグ名 | Google tag - Areum |
| タグの種類 | Googleタグ（Google Analytics配下にある場合もあります） |
| タグID | 手順2のG-… |
| 共有イベント設定 → イベント設定変数 | EVS - Areum common |
| トリガー | Initialization - All Pages（初期化・すべてのページ） |

保存します。ページビューはこのGoogleタグが自動で送る1回だけを使用します。`page_view`用のGA4イベントタグは追加しません。`send_page_view`をfalseにする設定も不要です。

同じG-…へ送るGoogleタグが既にある場合は、そのタグを再利用して共有設定を追加します。同じものをもう1個作らないでください。

### 4-D. クリックイベント用のトリガーを1個作る

「トリガー」→「新規」→「カスタムイベント」を開きます。

| 設定項目 | 入力・選択する内容 |
| --- | --- |
| トリガー名 | CE - booking_site_click |
| イベント名 | booking_site_click |
| 正規表現 | オフ |
| 発生場所 | すべてのカスタムイベント |

「すべて」は、上記イベント名に一致するものすべてという意味です。「クリック・リンクのみ」「すべての要素」のトリガーは作りません。

### 4-E. GA4クリックイベントタグを1個作る

「タグ」→「新規」→「Googleアナリティクス：GA4イベント」を開きます。

| 設定項目 | 入力・選択する内容 |
| --- | --- |
| タグ名 | GA4 - booking_site_click |
| 測定ID | 手順2と同じG-… |
| イベント名 | booking_site_click |
| イベント設定変数 | EVS - Areum common |
| トリガー | CE - booking_site_click |

さらに、イベントパラメータに次の2行を追加します。

| パラメータ名 | 値 |
| --- | --- |
| booking_url | {{DLV - booking_url}} |
| button_location | {{DLV - button_location}} |

これで共通設定の店舗情報3項目と合わせて5項目が送られます。タグの配信オプションは標準の「イベントごとに1度」にします。「ページごとに1度」にはしません。後から別の予約ボタンを押した操作も計測するためです。

タグは合計2個です。同じイベントをGA4の「イベントを作成」機能や別のクリックトリガーでも作らないでください。

公式：[GTM経由のGA4設定](https://support.google.com/tagmanager/answer/9442095?hl=ja)、[共通イベント設定](https://support.google.com/tagmanager/answer/13438771?hl=ja)

## 5. GA4の店舗・ボタン情報をレポートで使えるようにする

GA4「管理」→「データの表示」→「カスタム定義」→「カスタムディメンションを作成」を開き、次の5個を作成します。範囲はすべて「イベント」、イベントパラメータは右列の値です。

| ディメンション名 | イベントパラメータ |
| --- | --- |
| 店舗ID | store_id |
| 店舗名 | store_name |
| LP ID | lp_id |
| 予約先URL | booking_url |
| ボタン設置場所 | button_location |

続けて「管理」→「データの表示」→「イベント／キーイベント」で `booking_site_click` をキーイベントとして登録します。カスタム定義への追加はクリック自体を新しく発生させる操作ではありません。

この専用プロパティでは、遷移率の計算対象となるキーイベントは `booking_site_click` だけにします。他のキーイベントがある場合は、レポートで `booking_site_click` を選んで絞ります。キーイベントのカウント方法は「セッションごとに1回」にすると、キーイベント数を遷移した訪問回数として使いやすくなります。通常のクリック「イベント数」は後続のクリックも数えます。

カスタム定義を利用できるまで24〜48時間程度かかることがあり、過去に遡って同じ形で使えるとは限りません。登録は配信開始前に行ってください。

公式：[カスタム定義](https://support.google.com/analytics/answer/14240153?hl=ja)、[キーイベントの計測方法](https://developers.google.com/analytics/devguides/config/admin/v1/rest/v1beta/properties.keyEvents)

## 6. GitHubへ反映し、計測を確認して公開する

1. GitHubの既存LP保存場所に、今回の `index.html`・`assets` を同じフォルダ構成で反映します。既存画像フォルダも維持します。設定用IDを入れた `analytics-config.js` も含めます。元の大きな1ファイルHTMLだけでは今回のJavaScriptは動きません。
2. GitHub Pagesの公開処理完了後、GTM右上の「プレビュー」を押し、公開LPのURLを入れて接続します。GitHub管理画面のURLは入れません。
3. LPを読み込んだ時、`Google tag - Areum` が1回発火していることを確認します。
4. LPの予約ボタンを1回押します。元のタブを残したまま予約サイトが別タブに開きます。
5. Tag Assistantで `booking_site_click` を選択し、`GA4 - booking_site_click` が1回発火していることと、店舗名・予約先URL・設置場所が入っていることを確認します。
6. 以下の4か所をそれぞれ確認します。同じボタンを続けて試す場合は1秒以上空けます。

| 押した場所 | button_locationの値 |
| --- | --- |
| 初回料金の画像 | price_image |
| お試し案内の画像 | campaign_image |
| 「WEB予約・クーポンを確認する」 | campaign_button |
| 店舗情報の「WEB予約・空き状況を確認する」 | store_button |

7. GA4「管理」→「データの表示」→「DebugView」で、ページ読み込みの `page_view` と、1クリックにつき1個の `booking_site_click` が届くことを確認します。イベントを選択して店舗情報なども確認します。プレビューで届かない場合はTag Assistantのデバッグ設定を確認します。リアルタイムレポートも併用できます。
8. 確認後、GTM右上の「公開／送信」→バージョン名に `Areum 吉祥寺店 計測開始` と入力して公開します。プレビューだけでは通常の訪問者には反映されません。
9. プレビューを閉じて公開LPを通常表示し、GA4のリアルタイムにもイベントが届くことを確認します。検証の自分のクリックも計測に含まれます。

ここまで終われば、日常的なタグ管理作業は基本的に不要です。LP変更時と、定期的な数値確認の際に予約クリックが記録されることを確認してください。

## 7. Meta広告のリンクにUTMを付ける

広告から開く先は予約サイトではなく公開LPです。その公開LP URLの末尾に次の文字列を付けます。

```text
?utm_source=meta&utm_medium=paid_social&utm_campaign=areum_kichijoji&utm_content=creative_a
```

既にURLに `?` がある場合は、先頭を `&` にします。`creative_a` は広告素材を区別したいときの名前です。同じ広告には固定の名称を使い、個人情報は入れません。

MetaのURLパラメータ専用欄に入力する場合は先頭の `?` を除いた文字列を入れます。広告から実際にLPを開いて、アドレスにこれらのパラメータが付いていることを確認します。

GA4はLPのURLからUTMを読み取ります。今回のコードはそのURLを消したり、指定の予約先URLを変更したりしません。予約サイト側にUTMを付ける必要はありません。UTMのない過去の流入を、後から確実にMeta広告と判定することはできません。

公式：[UTMによるキャンペーンの識別](https://support.google.com/analytics/answer/10917952?hl=ja)

## 8. 数値を見る

### LP閲覧数・予約クリック数・クリック率

GA4「探索」→「自由形式」で、ディメンションに「店舗名」「LP ID」「イベント名」、指標に「イベント数」を追加します。行に「店舗名」、列に「イベント名」、値に「イベント数」を置きます。フィルタは `LP ID = areum-kichijoji`、イベント名は正規表現 `^(page_view|booking_site_click)$` にします。この探索を保存します。

- `page_view`列：LPの閲覧数。同じ人の再読み込みも増えます。
- `booking_site_click`列：予約ボタンのクリック数。異なる場所や後からのクリックは増えます。
- 閲覧数に対するクリック率：`booking_site_clickのイベント数 ÷ page_viewのイベント数 × 100`。例えば100閲覧・8クリックなら8%。複数クリックを数えるため、訪問者の割合とは異なり、100%を超える場合もあります。

### 「LPから予約サイトへ進んだ訪問の割合」を見る

実務上の遷移率としては「1回以上予約ボタンを押したセッション ÷ LPの全セッション」を推奨します。複数クリックでも1訪問として数えるため、上記クリック率と区別します。予約先の読み込み成功や予約完了は計測していません。

GA4「レポート」→「集客」→「トラフィック獲得」で、「セッションのキーイベント率」の対象を `booking_site_click` にします。このLP専用プロパティでは、この数値が訪問単位の遷移率です。キーイベントを選択するメニューがない画面では、このプロパティのキーイベントが `booking_site_click` だけになっていることを確認します。

他のLPや店舗も同じプロパティへ追加した場合は、対象LPのランディングページで絞り込んでから同じ数値を見ます。対象LP以外の全サイトセッションを分母にしないでください。

### ボタンの場所ごとに比較する

自由形式の探索で、行に「店舗名」「ボタン設置場所」、値に「イベント数」を入れ、イベント名を `booking_site_click`、LP IDを `areum-kichijoji` で絞ります。

### Meta広告だけに限定する

上記探索に「セッションの参照元／メディア」を追加し、`meta / paid_social` で絞ります。トラフィック獲得でも同じ参照元／メディアで絞り、対象キーイベントを `booking_site_click` にします。LP閲覧・クリック・遷移率はすべて同じ期間・同じ流入条件で比較します。クリックだけにMetaフィルタを掛けて、分母に全流入を使わないでください。

ブラウザの広告ブロック・同意設定・通信状況などの影響で、GA4の数値とMetaの数値が完全に一致するとは限りません。

公式：[トラフィック獲得](https://support.google.com/analytics/answer/12923437?hl=ja)、[セッションのキーイベント率の定義](https://developers.google.com/analytics/devguides/reporting/data/v1/api-schema#sessionKeyEventRate)
